# Agent Note: Markdown 预览打印

Status: implemented

[English](2026-09-18-markdown-preview-print.md) | 中文

## 问题

Markdown 预览以顺序文本页加载长文件。打印应用窗口会包含 Harness 导航和会话，却遗漏读者尚未到达的页面。若要求用户在打印前滚完整份文件，快捷键对长文档就不可靠。

## 决定

焦点位于渲染文档内时，Markdown 渲染器接受浏览器确认由用户输入的 Command-P 和 Control-P 事件。点击静态正文会聚焦文档，但不改变其可见布局。合成键盘事件不会开始打印。

文档 owner 提供 `requestTextCompletion`；仅当没有读取正在进行、文件尚未到达 `eof` 且当前读取没有失败时，它才请求下一文本页。待处理的打印请求会在每次累计前缀更新后调用此操作，直到 owner 报告 `eof`。读取失败会停止自动请求，由普通重试控件负责恢复读取。

完整文本可用后，渲染器在 `document.body` 下创建隐藏的 React portal，并在关闭流式模式后渲染同一 Markdown 源。打印媒体隐藏 Harness 根节点，只显示此副本，并应用页边距、代码换行、图片限宽、宽表收缩以及代码、表格和引用块的跨页保护。渲染器在下一动画帧调用捕获的原生 `window.print`，并在收到浏览器确认的 `afterprint` 事件后移除副本。

此功能与 [HTML 预览打印](2026-09-18-html-preview-print.zh.md)分开；后者启用脚本的 sandbox 需要能力 token 和临时启用 modal 的 iframe。

## 考虑过的替代方案

**打印可见预览子树。** 可见子树只包含已经加载的页面，并且位于可滚动的应用布局中，因此打印结果会依赖读者的滚动历史。

**预先完整加载每份 Markdown 文件。** 这会取消普通阅读的分页，即使用户从不打印也会增加内存、解析和传输成本。

**打印前把 Markdown 转为 PDF。** 浏览器已经能为渲染后的文档分页，此方案却引入了独立的文档生成器和下载生命周期。

## 结果

Markdown 打印补齐阅读器使用的同一条版本感知分页序列，不请求第二个整文件接口。可见预览增加了程序化焦点目标，使快捷键具有准确作用范围。临时副本只在打印时重复渲染，屏幕上不可见。单元覆盖固定快捷键认证与焦点行为；浏览器快照通过滚动加载一页，通过打印加载最后一页，确认打印媒体隐藏 Harness 外壳且宽表收进打印副本内，并确认它在 `afterprint` 后清理。
