# Agent Note：紧凑的 Markdown 文档预览

Status: implemented

[English](2026-09-20-compact-markdown-document-preview.md) | 中文

## 问题

文档预览沿用对话 Markdown 较为宽松的纵向节奏。较长的运维文档在一屏内显示的行数偏少，标题与后续内容相距较远，表格主要依赖细分隔线区分相邻数据。放大右侧面板只会增加行宽，没有形成稳定的阅读栏。共享 Markdown 渲染器还服务于聊天消息，修改其基础样式会同时改变另一种阅读场景。

## 决定

Markdown 文档正文持有仅用于文档的阅读样式。阅读栏居中且最大宽度为 960px，沿用现有的 14px 内容字号设置，默认行高为 21px，并为标题、段落、列表、代码块、引用和分隔线使用更小且分级的间距。较长的路径和标识符仍可在任意位置换行。

表格使用 20px 行高、上下 6px 和左右 10px 的单元格内边距，并通过跟随主题的底色区分表头与正文单元格。单元格保留 88px 最小宽度。共享渲染器现有的表格宽度规则继续生效：少于四列的表格占满阅读栏，列数更多的表格保持自然宽度和横向滚动。同一个阅读样式类也应用于临时打印文档；打印专用规则仍可缩减单元格宽度并让宽表换行适配纸张。

这些覆盖样式归文档预览包所有。无 Cordis 依赖的 Markdown 基础组件与聊天视图保持原有的字号和间距。

## 曾考虑的替代方案

**修改共享 Markdown 样式表。** 这会让聊天回复也变得紧凑，但用户反馈针对的是文件阅读，并会把行宽与浏览方式不同的两个场景耦合起来。

**缩小全局内容字号。** 全局设置会同时改变聊天、工具、源码预览和控件，而当前问题主要来自文档间距和表格呈现，并非字形尺寸本身。

**只压缩表格。** 更紧凑的单元格能改善对照阅读，但标题、段落与列表之间仍会占用过多高度。

## 后果

运维类 Markdown 在同一面板中显示更多内容，表格也通过间距和表面明暗呈现清晰的行列分组。超宽表格在屏幕上仍可横向滚动，因此紧凑排版不会丢弃内容或强制生成过窄的列。无密钥浏览器文档预览场景会先测量阅读栏最大宽度、居中位置、文字节奏、单元格内边距和主题底色，再执行现有的完整文档打印流程。此决定不增加密度开关；需要更大文字的用户继续使用现有的内容字号设置。
